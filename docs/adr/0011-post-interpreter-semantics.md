# ADR-0011: Post-processor interpreter semantics

Date: 2026-10-24 · Status: accepted (director, 2026-10-24)

## Context
ADR-0004 adopts the `.pp` template grammar but leaves many interpretation details open: how lines are classified, how missing blocks behave, when modal variables restate, how incremental output, inverse time and rotary wrapping are expressed. T-0030 had to pick answers; this records them so later posts and features build on the same rules.

## Decision
1. **Line classes.** Blank lines and lines whose first non-blank character is `+` are comments. Outside a block: `VAR NAME = [spec]`, `begin NAME`, or `KEY = value` (value optionally double-quoted). Inside a block: a comment, `end`, or a **double-quoted output line**. Anything else is an error naming the line. (This is the form community posts use, which ADR-0004 exists to support; see the note under Consequences.)
2. **Errors vs warnings.** Unknown block names and unknown settings are warnings; the block is stored but never emitted. Unknown tags in a VAR or in a `[tag]` reference, malformed VARs, invalid setting values, unbalanced `begin`/`end` and unquoted block lines are errors carrying the 1-based line. Duplicate blocks/VARs warn and the last one wins.
3. **VAR spec** `[tag|mode|prefix|format|multiplier]`: mode `A` (always) or `C` (only when the rendered text changed), optionally suffixed `I` (`AI`/`CI`) for **incremental** output, allowed only on X, Y, Z, A. Incremental values are `round(end) − round(start)` of the current move at the format's precision, so deltas telescope without drift. Prefix is verbatim (spaces significant). Format `[+]W.D`: forced sign, minimum integer digits (zero padded), decimals. Rounding is half away from zero, `-0` is never written, formatting is locale independent. Multiplier (default 1) applies after unit conversion. Tags referenced without a VAR use an implicit always/no-prefix/3-decimal format (integers for N, T, TP, S).
4. **Program flow.** HEADER; then for each toolpath with moves: modal memory is cleared, then TOOLCHANGE + SPINDLE_ON if the tool (number or name) differs from the previous toolpath's, otherwise NEW_SEGMENT (for the first toolpath only when `FIRST_TOOLPATH_NEW_SEGMENT = YES`); one block per move; FOOTER. Toolpaths without moves are skipped, including their tool change. Header values come from the first non-empty toolpath; position tags outside moves report the current position (the job's home before the first move).
5. **Block fallbacks.** `INITIAL_RAPID_MOVE`, `FIRST_FEED_MOVE`, `FIRST_PLUNGE_MOVE`, `FIRST_*_ARC_MOVE`, `FIRST_*_HELICAL_ARC[_PLUNGE]_MOVE` apply to the first such move of each toolpath and fall back to the plain block. Helical blocks fall back to the arc block (which then carries Z). PLUNGE_MOVE and RETRACT_MOVE fall back to FEED_MOVE; RAPID_MOVE falls back to FEED_MOVE with a run warning; a move with no usable block is a run error. A missing DWELL_MOVE drops dwells with a warning. HEADER, FOOTER, TOOLCHANGE, NEW_SEGMENT, SPINDLE_ON and FEED_RATE_CHANGE are simply skipped when absent. FEED_RATE_CHANGE, when present, is written before a cutting move whose feed differs from the last one written.
6. **Arcs.** `[I] [J]` are centre minus start; `[IA] [JA]` absolute centre; `[Radius]` is negative for sweeps over 180°; `[Angle]` is the sweep in degrees. An arc is linearised into feed moves (chordal deviation ≤ `PostContext::arcTolerance`, default 0.01 mm, Z interpolated) when the post lacks the plain `CW_ARC_MOVE`/`CCW_ARC_MOVE` block, when its radius is outside `MIN_ARC_RADIUS`/`MAX_ARC_RADIUS`, or when a rotary wrap is active. When the arc blocks reference `[Radius]` but no centre tag, full circles are written as two half circles.
7. **Units and feeds.** `UNITS = "INCHES"` divides length tags and feed tags (F, FC, FP) by 25.4; angles, spindle speed, counts, seconds and inverse time are not converted. `[F]` is the current move's feed (override, else the tool's feed or — for plunge/retract — plunge rate; rapids report the last feed). `[FI]` is feed ÷ move length (1/min); `INVERSE_TIME_MODE = YES` makes `[F]` on cutting moves equal `[FI]`.
8. **Rotary wrap.** `ROTARY_WRAP_X/Y = "A"` (or `"-A"`) converts that linear axis to degrees, `360·v / (π·D)` with D = `PostContext::rotaryDiameter`, rendered through `[A]`; the wrapped linear tag renders empty. Wrapping without a diameter is a run error. Setting both is a parse error.
9. **Line numbers.** `[N]` takes the current number and advances by `LINE_NUMBER_INCREMENT`; once it would exceed `LINE_NUMBER_MAXIMUM` it restarts at `LINE_NUMBER_START`. A line whose every tag rendered empty is dropped; a literal `""` line is written as an empty line. Trailing whitespace is trimmed.
10. **Determinism.** Date, time, file names and product string come from `PostContext`; no clock or filesystem access. `SUBSTITUTE` pairs apply to text tags only.
11. **Errors** use a small `Result<T>` (value or `Error{line, message}`), since `std::expected` is C++23 and the project is C++20.

Settings stored but not yet acted on (kept in `PostSettings::raw`): PRINT_DIRECT, DIRECT_OUTPUT, RAPID_SPEED, MAXIMUM_LENGTH, MAXIMUM_ROTATION, SPINDLE_SPEED_RANGE, TAPE_SPLITTING, and the behaviour of RAPID_PLUNGE_TO_STARTZ (parsed into a flag; toolpaths do not yet carry a start-Z). Laser, keep-out-zone, drill-bank and cutter-comp blocks are recognised but never emitted until those features exist; their tags evaluate to 0/empty.

## Consequences
- `+` lines are comments and quoted lines are output, matching existing community posts (ADR-0004). The T-0030 card was amended by the director to say the same.
- `[TOOLPATH_NAME]` and Y/Z material tags (`YMIN` … `ZLENGTH`) are accepted in addition to the inventory list.
- Golden tests compare the shipped `posts/grbl_mm.pp` against `core/tests/golden/post/grbl_square.nc`.
