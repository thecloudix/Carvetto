# ADR-0033: Text core (FreeType + HarfBuzz, deterministic layout, hostile-input bounds)

Date: 2026-11-07 · Status: proposed (T-0130)

## Context
The `text` module of ARCHITECTURE.md turns font bytes and a UTF-8 string into contours the rest of
the core can cut: `Font`, `layoutText` (blocks), `layoutTextOnPath` (text along a curve). The project
owner decided on 2026-11-07 to use FreeType and HarfBuzz together ("as the plan originally said").
Requirements: contours identical on every platform for the same bytes, no system fonts, no Qt, mm
and radians, and bounded work on hostile fonts and strings.

## Decision

### 1. Dependencies and licences
- **FreeType 2.14.3** (tag `VER-2-14-3`, commit `0a0221a1347e2f1e07c395263540026e9a0aa7c7`), fetched with
  `FetchContent` like Clipper2. FreeType is dual-licensed (FreeType License, or GPLv2 or later). We use
  it **under the FreeType License (FTL)**: the FTL is incompatible with GPLv2 but, as FreeType's own
  `LICENSE.TXT` states, compatible with GPLv3, and Carvetto is GPL-3.0-or-later. The FTL's advertising
  clause is satisfied by the credit line in `THIRD_PARTY_NOTICES.md` ("portions of this software are
  copyright The FreeType Project, www.freetype.org. All rights reserved"), which must ship with
  binaries. Built with `FT_DISABLE_{ZLIB,BZIP2,PNG,HARFBUZZ,BROTLI}`: no compressed (gzip, WOFF,
  WOFF2) fonts and no colour/bitmap formats.
- **HarfBuzz 15.1.0** ("Old MIT" licence, GPL compatible), release tarball pinned by SHA-256, built
  from its single-file amalgamation (`src/harfbuzz.cc`) as a private static library
  `carvetto_harfbuzz`: no FreeType/GLib/ICU/CoreText/DirectWrite back ends, no subsetter, no
  upstream CMake. Shaping uses HarfBuzz's built-in Unicode data and OpenType code only, so it does
  not depend on the operating system.
- Both are PRIVATE dependencies of `carvetto_core` and SYSTEM includes; no FreeType or HarfBuzz header
  is included from a public Carvetto header. Neither is vendored in the repository: CI and the cloud
  workspace can reach github.com (as for Clipper2, Catch2 and miniz).
- The test font is a **Carvetto original** (`core/tests/fixtures/text/CarvettoTest-Regular.ttf`, 1.6
  KB, generated byte-reproducibly by `tools/make_test_font.py`) under the **SIL OFL 1.1**
  (`OFL.txt` beside it; the licence text is also in the font's `name` table). No third-party font is
  copied or derived; it is used by tests only and is not shipped.

### 2. Determinism
- Fonts are loaded from bytes or an explicit path; there is no system-font enumeration and no
  fallback. Only sfnt containers (`0x00010000`, `true`, `OTTO`, `ttcf` face 0) reach FreeType; other
  formats (Type 1, BDF, PCF, WOFF, ...) are refused before parsing, which also shrinks the attack
  surface to FreeType's sfnt/TrueType/CFF code.
- Outlines are loaded with `FT_LOAD_NO_SCALE | NO_HINTING | NO_AUTOHINT | NO_BITMAP`: no hinting
  and no rounding to pixels; coordinates are the font's own integers. Shaping runs with the
  HarfBuzz font scale equal to `unitsPerEm`, so advances and offsets are integers in font units.
- The conversion to millimetres is one expression everywhere: `mm = (units * sizeMm) / unitsPerEm`
  (one multiply and one divide in IEEE double, correctly rounded on every platform). Positions add
  these terms; there is no accumulation of a float pen. `core` is built with `-ffp-contract=off` /
  `/fp:precise` (ADR-0025 section 11), so no fused multiply-add changes the last bit.
- Quadratic outline segments are elevated exactly to cubic Beziers, `C1 = (P0 + 2Q) / 3`,
  `C2 = (P2 + 2Q) / 3`, before scaling. Contours are closed lines/cubics; zero-length lines are dropped.
- Orientation is normalised: outer contours counter-clockwise (positive area), holes clockwise, for
  TrueType-style (FreeType default) and PostScript-style (`FT_OUTLINE_REVERSE_FILL`) outlines.
- Shaping language is fixed (`TextStyle::language`, default "en"), never the process locale
  (`hb_buffer_guess_segment_properties` would otherwise ask `setlocale`). Script and direction are
  guessed from the text by HarfBuzz's own tables, or forced by `TextStyle::direction`.
- Text on a curve uses no trigonometry for lines and Beziers (rotation is the unit tangent vector;
  only `+ - * /` and `sqrt` are used, all correctly rounded), so those results are bit-identical
  across platforms. Arc spans of the guide contour use `sin/cos` through `geometry::ArcSpan` and are
  accurate but not guaranteed to be bit-identical across C libraries. The tests check hashes of the
  line and Bezier cases only.

### 3. Layout model
- `TextStyle::sizeMm` is the **em size** (1 em = `unitsPerEm` units), not the cap height; the text
  tool (T-0211) can offer a cap-height convenience later.
- Lines split at LF, CRLF and CR and are shaped independently (HarfBuzz does no bidi reordering across
  runs; a line is one direction run, which is right for single-script lines, and a documented
  limitation for mixed LTR/RTL lines). First baseline at y = 0, later lines go down by
  `lineHeight * sizeMm / unitsPerEm * lineSpacing` (the font's hhea/OS2 line height). Alignment
  (left/centre/right) is per line about x = 0. Letter spacing is added after every glyph, so it does
  not change the shaped advances and the line width counts it between glyphs only.
- Kerning is whatever the font provides through HarfBuzz (`kern` table or GPOS `kern`);
  `TextStyle::kerning = false` turns the `kern` feature off. A legacy `kern` pair is split by HarfBuzz
  between the first glyph's advance and the second glyph's advance and offset, so a glyph's drawn
  origin (`PlacedGlyph::origin`) can differ from its pen position; `origin` is always the drawn one.
- Missing characters produce glyph 0 (`.notdef`), flagged `PlacedGlyph::missing`; invalid UTF-8 is
  replaced (HarfBuzz) and flagged `replacedInvalidUtf8`. Combining marks keep their base's cluster and
  are placed by HarfBuzz (GPOS, or its fallback mark placement).
- Text on a curve places each glyph rigidly: the midpoint of its advance on the baseline goes to the
  path point at that arc length, its baseline direction is the path tangent there, and up is the
  path's left side (reverse the contour for the other side). The guide is arc-length parametrised
  exactly for lines, by angle for arcs, and for Beziers through a table of 64 parameter steps (3-point
  Gauss-Legendre arc lengths) refined by 3 Newton steps on the exact in-cell length; the tangent is
  the exact derivative. Closed guides wrap (`fmod`); on open guides, glyphs whose midpoint is off
  either end are dropped and `truncated` is set. Glyphs are not bent to the curve: tight curves show
  the gaps/overlaps of rigid placement (bending is a later option).

### 4. Hostile-input bounds (statuses, no partial results)
Style: size must be finite, > 0 and <= `maxSizeMm` (default 10 000, never above 1e6); letter spacing
finite and within the same bound; line spacing in [0, 100]; the language a short BCP 47 tag.
`TextLimits` (all clamped to absolute ceilings so a caller cannot remove them): text bytes (1 MiB; 64
MiB ceiling), code points, lines, glyphs, spans (emitted, and separately decoded from the font), outline
points per glyph, guide spans, and a **work meter** `TextLayout::work` = code points + 4 per shaped
glyph + outline points per distinct glyph decoded + spans emitted (+ path table setup and 8 per glyph on
a curve). It is a pure function of the input, so a refusal is reproducible. Any breach returns
`TextStatus::{TextTooLong, TooManyCodePoints, TooManyLines, TooManyGlyphs, TooManySpans,
PathTooComplex, WorkLimit}` with empty output, in the style of the geometry statuses; invalid
style/font/path return `InvalidStyle`, `InvalidFont`, `InvalidPath`. A glyph with more points than
`maxGlyphPoints`, or one FreeType refuses, is skipped (`skippedGlyphs`) rather than failing the text.
Empty text is Ok with no glyphs. Font loading bounds file size (32 MiB default, 256 MiB ceiling),
glyph count and em size; failures are `FontStatus` values. HarfBuzz and FreeType have their own
limits against pathological tables; our counters bound everything we do around them.

### 5. Corrupt-font testing
`core/tests/text/fuzz_test.cpp` mutates the test font deterministically (random bytes, directory bytes,
32-bit extremes, truncation, block copies, bit flips; 4 000 iterations, each loaded, decoded and laid
out in both modes) and requires a clean refusal or a finite, bounded layout. The same test is run under
`-fsanitize=address,undefined` before every release of this module (results recorded in the task
report); CI's sanitizer job, if added, only needs to build with those flags. Known limit: FreeType and
HarfBuzz are fuzzed continuously upstream (OSS-Fuzz); we add our own bounds, not a replacement.

### 6. Out of scope
Single-line (stroke) fonts, system-font discovery, variable-font axes (the default instance is used),
colour/SVG/bitmap glyphs, WOFF/WOFF2, vertical text, bidi reordering within a line, glyph bending,
and the text tool UI (T-0211).
