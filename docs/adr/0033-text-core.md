# ADR-0033: Text core (FreeType + HarfBuzz, deterministic layout, hostile-input bounds)

Date: 2026-11-07 · Status: proposed (T-0130)

## Context
The `text` module of ARCHITECTURE.md turns font bytes and a UTF-8 string into contours the rest of
the core can cut: `Font`, `layoutText` (blocks), `layoutTextOnPath` (text along a curve). The project
owner decided on 2026-11-07 to use FreeType and HarfBuzz together ("as the plan originally said").
Requirements: contours identical on every platform for the same bytes, no system fonts, no Qt, mm
and radians, and bounded work on hostile fonts and strings.

## Decision

### 1. Dependencies and licences
- **FreeType 2.14.3** (tag `VER-2-14-3`, commit `0a0221a1347e2f1e07c395263540026e9a0aa7c7`), fetched with
  `FetchContent` like Clipper2. FreeType is dual-licensed (FreeType License, or GPLv2 or later). We use
  it **under the FreeType License (FTL)**: the FTL is incompatible with GPLv2 but, as FreeType's own
  `LICENSE.TXT` states, compatible with GPLv3, and Carvetto is GPL-3.0-or-later. The FTL's advertising
  clause is satisfied by the credit line in `THIRD_PARTY_NOTICES.md` ("portions of this software are
  copyright The FreeType Project, www.freetype.org. All rights reserved"), which must ship with
  binaries. Built with `FT_DISABLE_{ZLIB,BZIP2,PNG,HARFBUZZ,BROTLI}`; additionally our own option header
  (`core/src/text/freetype_options.h`, selected with `FT_CONFIG_OPTIONS_H`) undefines
  `FT_CONFIG_OPTION_USE_ZLIB` (so the bundled zlib is not compiled in: no gzip, WOFF; WOFF2 needs Brotli)
  and `FT_CONFIG_OPTION_ENVIRONMENT_PROPERTIES` (FreeType would otherwise read `FREETYPE_PROPERTIES`).
  FreeType's other drivers (Type 1, CID, BDF, PCF, ...) are still compiled into the library but are
  unreachable, because `Font::load` only passes sfnt-magic data on. FreeType's debug-level getenv
  paths (`FT2_DEBUG`, ...) exist only in builds defining `FT_DEBUG_LEVEL_*`, which we do not.
- **HarfBuzz 15.1.0** ("Old MIT" licence, GPL compatible), release tarball pinned by SHA-256, built
  from its single-file amalgamation (`src/harfbuzz.cc`) as a private static library
  `carvetto_harfbuzz`: no FreeType/GLib/ICU/CoreText/DirectWrite back ends, no subsetter, no
  upstream CMake. Shaping uses HarfBuzz's built-in Unicode data and OpenType code only, so it does
  not depend on the operating system. It is compiled with `HB_NO_GETENV` (no `HB_SHAPER_LIST`,
  `HB_FACE_LOADER` or `HB_FONT_FUNCS`) and shaping calls `hb_shape_full` with the explicit shaper list
  `{"ot"}`. The environment test executable is registered several times in ctest, each process launched with these variables (and `FREETYPE_PROPERTIES`) already set, and every run must reproduce the same hashes.
- Both are PRIVATE dependencies of `carvetto_core` and SYSTEM includes; no FreeType or HarfBuzz header
  is included from a public Carvetto header. Neither is vendored in the repository: CI and the cloud
  workspace can reach github.com (as for Clipper2, Catch2 and miniz).
- The test font is a **Carvetto original** (`core/tests/fixtures/text/CarvettoTest-Regular.ttf`, 1.6
  KB, generated byte-reproducibly by `tools/make_test_font.py`) under the **SIL OFL 1.1**
  (`OFL.txt` beside it; the licence text is also in the font's `name` table). No third-party font is
  copied or derived; it is used by tests only and is not shipped.

### 2. Determinism
- Fonts are loaded from bytes or an explicit path; there is no system-font enumeration and no
  fallback. Only sfnt containers (`0x00010000`, `true`, `OTTO`, `ttcf` face 0) reach FreeType; other
  formats (Type 1, BDF, PCF, WOFF, ...) are refused before parsing, which also shrinks the attack
  surface to FreeType's sfnt/TrueType/CFF code.
- Outlines are loaded with `FT_LOAD_NO_SCALE | NO_HINTING | NO_AUTOHINT | NO_BITMAP`: no hinting
  and no rounding to pixels; coordinates are the font's own integers. Shaping runs with the
  HarfBuzz font scale equal to `unitsPerEm`, so advances and offsets are integers in font units.
- The conversion to millimetres is one expression everywhere: `mm = (units * sizeMm) / unitsPerEm`
  (one multiply and one divide in IEEE double, correctly rounded on every platform). Positions add
  these terms; there is no accumulation of a float pen. `core` is built with `-ffp-contract=off` /
  `/fp:precise` (ADR-0025 section 11), so no fused multiply-add changes the last bit.
- Quadratic outline segments are elevated exactly to cubic Beziers, `C1 = (P0 + 2Q) / 3`,
  `C2 = (P2 + 2Q) / 3`, before scaling. Contours are closed lines/cubics; zero-length lines are dropped.
- Orientation is normalised: outer contours counter-clockwise (positive area), holes clockwise, for
  TrueType-style (FreeType default) and PostScript-style (`FT_OUTLINE_REVERSE_FILL`) outlines.
- Hostile line-break floods are linear: the byte limit is checked before any copy, and text on a
  curve converts line breaks to spaces in one pass (a CPU-time test covers both entry points).
- Shaping language is fixed (`TextStyle::language`, default "en"), never the process locale
  (`hb_buffer_guess_segment_properties` would otherwise ask `setlocale`). Script and direction are
  guessed from the text by HarfBuzz's own tables, or forced by `TextStyle::direction`.
- Text on a curve uses no trigonometry for lines and Beziers (rotation is the unit tangent vector;
  only `+ - * /` and `sqrt` are used, all correctly rounded), so those results are bit-identical
  across platforms. Arc spans of the guide contour use `sin/cos` through `geometry::ArcSpan` and are
  accurate but not guaranteed to be bit-identical across C libraries. The tests check hashes of the
  line and Bezier cases only.

### 3. Layout model
- `TextStyle::sizeMm` is the **em size** (1 em = `unitsPerEm` units), not the cap height; the text
  tool (T-0211) can offer a cap-height convenience later.
- Lines split at LF, CRLF and CR and are shaped independently (HarfBuzz does no bidi reordering across
  runs; a line is one direction run, which is right for single-script lines, and a documented
  limitation for mixed LTR/RTL lines). First baseline at y = 0, later lines go down by
  `lineHeight * sizeMm / unitsPerEm * lineSpacing` (the font's hhea/OS2 line height). Alignment
  (left/centre/right) is per line about x = 0. Letter spacing is added after every glyph, so it does
  not change the shaped advances and the line width counts it between glyphs only.
- Kerning is whatever the font provides through HarfBuzz (`kern` table or GPOS `kern`);
  `TextStyle::kerning = false` turns the `kern` feature off. A legacy `kern` pair is split by HarfBuzz
  between the first glyph's advance and the second glyph's advance and offset, so a glyph's drawn
  origin (`PlacedGlyph::origin`) can differ from its pen position; `origin` is always the drawn one.
- Missing characters produce glyph 0 (`.notdef`), flagged `PlacedGlyph::missing`; invalid UTF-8 is
  replaced (HarfBuzz) and flagged `replacedInvalidUtf8`. Combining marks keep their base's cluster and
  are placed by HarfBuzz (GPOS, or its fallback mark placement).
- Text on a curve places each glyph rigidly: the midpoint of its advance on the baseline goes to the
  path point at that arc length, its baseline direction is the path tangent there, and up is the
  path's left side (reverse the contour for the other side). The guide is arc-length parametrised
  exactly for lines, by angle for arcs, and for Beziers through a table of 64 parameter steps (3-point
  Gauss-Legendre arc lengths) refined by 3 Newton steps on the exact in-cell length; the tangent is
  the exact derivative. Closed guides wrap (`fmod`); on open guides, glyphs whose midpoint is off
  either end are dropped and `truncated` is set. Glyphs are not bent to the curve: tight curves show
  the gaps/overlaps of rigid placement (bending is a later option).

### 4. Hostile-input bounds (statuses, no partial results)
Style: size must be finite, > 0 and <= `maxSizeMm` (default 10 000, never above 1e6); letter spacing
finite and within the same bound; line spacing in [0, 100]; the language a short BCP 47 tag.
`TextLimits` (all clamped to absolute ceilings so a caller cannot remove them): text bytes (1 MiB; 64
MiB ceiling), code points, lines, glyphs, spans (emitted, and separately decoded from the font), outline
points per glyph, guide spans, and a **work meter** `TextLayout::work` = code points + 4 per shaped
glyph + outline points per distinct glyph decoded + spans emitted (+ path table setup and 8 per glyph on
a curve). It is a pure function of the input, so a refusal is reproducible. Any breach returns
`TextStatus::{TextTooLong, TooManyCodePoints, TooManyLines, TooManyGlyphs, TooManySpans,
PathTooComplex, WorkLimit}` with empty output, in the style of the geometry statuses; invalid
style/font/path return `InvalidStyle`, `InvalidFont`, `InvalidPath`. A glyph with more points than
`maxGlyphPoints`, or one FreeType refuses, is skipped (`skippedGlyphs`) rather than failing the text.
Empty text is Ok with no glyphs. Font loading bounds file size (32 MiB default, 256 MiB ceiling),
glyph count and em size; failures are `FontStatus` values. HarfBuzz and FreeType have their own
limits against pathological tables; our counters bound everything we do around them.

### 5. Corrupt-font testing
`core/tests/text/fuzz_test.cpp` mutates the test font deterministically (random bytes, directory bytes,
32-bit extremes, truncation, block copies, bit flips; 4 000 iterations, each loaded, decoded and laid
out in both modes) and requires a clean refusal or a finite, bounded layout. The same test is run under
`-fsanitize=address,undefined` before every release of this module (results recorded in the task
report); CI's sanitizer job, if added, only needs to build with those flags. Known limit: FreeType and
HarfBuzz are fuzzed continuously upstream (OSS-Fuzz); we add our own bounds, not a replacement.

### 6. Out of scope
Single-line (stroke) fonts, system-font discovery, variable-font axes (the default instance is used),
colour/SVG/bitmap glyphs, WOFF/WOFF2, vertical text, bidi reordering within a line, glyph bending,
and the text tool UI (delivered by T-0211, amendment A1).

## Amendment A1 (T-0211): text objects, embedded fonts, the Text tool

Date: 2026-11-08 · Status: proposed

### 1. The text object
Text is a `VectorObject` whose creation parameters are a new kind, `TextParams` (the existing
"parameters that produced the contours" convention of ADR-0013): the string, the embedded font's
key, em size, alignment, letter and line spacing, kerning, a mode and a placement. Reusing the vector
payload means selection, snapping, boolean/offset operations, transforms and toolpaths work on text
with no new code path: a toolpath selects the glyph contours like any other vector.
- **Contours are a cached derived view.** `buildTextContours` (core/document, on top of `layoutText`
  and `layoutTextOnPath`) computes them; the commands store the result in the object next to the
  parameters, and the `.carv` loader trusts the stored contours and never re-lays out. So opening a
  file does not depend on FreeType/HarfBuzz output, save -> load -> save is byte-stable, and a file
  whose font cannot be parsed still opens, cuts and displays. The editor recomputes the contours
  whenever a parameter changes. A test checks that re-laying out a loaded object reproduces its
  stored contours.
- **Layout is in a local frame**; `placement` (a `Transform2`) maps it into the sheet. Any affine
  transform (move, rotate, scale, mirror, array copy) composes into `placement` and is applied to the
  contours too, so text stays editable after being transformed (a mirror also reverses the contours
  so outer ones stay counter-clockwise). Node editing, boolean operations and offsets still turn a
  text into plain curves (`NoParams`) because they change the contours; the existing rule of
  ADR-0030.
- **Modes.** *Point*: lines grow from a baseline anchor at the local origin. *Box*: the local box is
  x in [0, w], y in [-h, 0]; words wrap greedily at the box width (word widths come from shaping each
  word alone and adding the shaped space advance and letter spacing, so kerning across a space is
  ignored when choosing breaks; not when drawing); the first baseline is one ascender below the top;
  alignment is about the box edges; an over-wide word or a text taller than `h` sets an `overflow`
  flag (reported, not clipped). Wrapping is bounded: more than 4 000 words is refused. *Curve*: the
  guide contour is **snapshotted into the parameters** (local frame) together with the id of the
  object it came from (informational). A snapshot, not a live link, because live links need
  dependency tracking and dangling-reference rules for deleted or edited guides; moving the guide
  does not move the text, and the editor re-picks a guide to refit. Text on a curve runs along the
  guide in its own direction; "reverse guide" flips it. On a closed guide the text wraps around and
  very long text may overlap itself (no stop at one full turn).
- **Convert to curves** (`ConvertTextToCurvesCommand`) sets the parameters to `NoParams` and keeps
  the contours; one undo step for the whole selection, restored exactly by undo.
- Limits: text at most 256 KiB, parameters finite and in range (`textParamsProblem`), the layout
  limits of section 4 apply to every layout. The document integrity check reports a text whose font
  is not embedded (`MissingFont`).

### 2. Embedded fonts (embedding policy)
Font bytes are **embedded in the `.carv`** as members `fonts/<key>.font`, where `<key>` is the
FNV-1a 64 hash of the bytes as 16 hex digits, so the same font is stored once and files are portable:
no system font is ever referenced and the file looks the same on every machine. (FNV-1a is a key, not
a security measure: `Document::insertFont` refuses a different font under a taken key, and the loader
recomputes the hash of every font member and refuses a file whose bytes do not match their name.)
Commands that embed a font check `Document::fontProblem` first: the Text tool and the DXF import refuse
(with a message naming the cap) instead of adding a text object without its font. Caps: 8 MiB per font, 32 MiB and 64 fonts per document; the loader and
the saver refuse more (`ResourceLimit`). Only fonts a text object uses are written (unused ones are
dropped at save); the user has no font-licence prompt, so **embedding is the user's decision to make
for fonts they pick**; the bundled starter font is DejaVu Serif (Bitstream Vera licence, redistributable; amendment A2). Fonts are parsed by `core/text` only when
text is edited, never when a file is opened. Member names `fonts/*.font` are reserved in
`CarvExtras::withMember`.

### 3. Format version (ADR-0021 section 5 amended)
The format becomes **1.2**: text parameters (`"type": "text"`) and font members are optional
additions. A document without text is still written as **1.1** (byte-identical to before), so only
files that use text carry 1.2. Older readers: a 1.1 reader keeps the unknown parameter kind verbatim
(the ADR-0013 unknown-parameter path), shows and cuts the stored contours as plain curves, keeps the
`fonts/` members as unknown members and writes both back unchanged on save; nothing is lost and no
error appears. Newer files with a higher *major* are refused as before.

### 4. The Text tool (viewmodel)
`TextEditor` (owned by `ToolController`, `ToolKind::Text`) follows ADR-0027/0030 conventions:
- **Gesture-frozen draft.** The text being typed lives only in the editor until `commit()`; the
  document is not touched while typing, so a draft needs no undo and is discarded by Escape. The draft
  holds copies of its font bytes and guide, and `setDocument` drops it without dereferencing either
  document: a replaced or freed document cannot be reached (tested, including under ASan).
- **Commit is one undo step** (a `MacroCommand` of `AddFontCommand` and `AddObjectCommand` or
  `SetTextCommand`). Editing in place re-lays out the whole object; committing without a change
  records nothing.
- **Fonts** come from bytes/files the user or app supplies; the app compiles in the DejaVu Serif starter font
  (`data/fonts`, amendment A2); the file dialog picks a TTF/OTF. No system font enumeration anywhere in core.
- Typing has no caret: characters append, Backspace removes the last code point, and the full text
  can be replaced (`setText`). Caret navigation is a follow-up.

### 5. DXF TEXT / MTEXT import
`importDxfIntoDocument` maps each parsed text item onto a Text object when the caller supplies a font
(the app passes the Text tool's current font): character height becomes the em size through the
font's cap height; rotation, width factor and mirroring go into `placement`; left/centre/right
justification becomes the alignment; top/middle vertical attachment moves the first baseline; an
MTEXT reference width makes text in a box. DXF font names are never resolved. Without a usable font
the text is skipped with a warning, as before.

DXF justification follows the specification: for a justified TEXT the second alignment point (group 11)
is the anchor; Aligned/Fit run the baseline from group 10 to group 11 (Aligned scales the height too,
Fit only the width); Bottom attachment lifts the baseline by the descender. The upside-down generation
flag is not read by the importer and is ignored. Text drawn with `.notdef` boxes because the font lacks
glyphs produces an import warning.

## Amendment A2 (T-0233): DejaVu Serif is the starter font

Owner decision 2026-11-08. The placeholder starter font is replaced by **DejaVu Serif 2.37 Regular**
(no Bold: the Text tool has no bold option), vendored unmodified as `data/fonts/DejaVuSerif.ttf` (380132
bytes, SHA-256 `42d1edeb7952f31b1f96d767ed7030b08a39e0c372b0071641518864e2bffb51`) with the upstream
`LICENSE` as `data/fonts/DEJAVU-LICENSE.txt`. Source: official release
`dejavu-fonts-ttf-2.37.tar.bz2` from github.com/dejavu-fonts/dejavu-fonts (tag `version_2_37`),
tarball SHA-256 `fa9ca4d13871dd122f61258a80d01751d603b4d3ee14095d65453b4e846e17d7`. The licence
(Bitstream Vera, DejaVu changes public domain) permits redistribution; the font must not be modified
under the same name and may not be sold by itself. The font is compiled in by the existing
`starter_font.hpp` mechanism; its display name is "DejaVu Serif". Tests keep the tiny Carvetto test
font except for the starter-font coverage tests. Embedding the full font in a `.carv` costs about
380 KB, far below the 8 MiB per-font cap.
